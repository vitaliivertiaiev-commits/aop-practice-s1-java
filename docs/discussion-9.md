# Практична 9. Дискусія

## 1. Навіщо виносити код у функцію, якщо він працює?

Функція дає назву окремій дії, прибирає повторення і дозволяє перевірити
її незалежно від решти програми. У задачі 1512 підрахунок частот відділено
від підрахунку пар, а в 1431 пошук максимуму — від формування відповіді.
Не варто ділити код лише заради кількості функцій: кожна має мати зрозумілу роль.

## 2. Чим параметр відрізняється від аргументу?

Параметр — змінна в оголошенні функції, аргумент — значення під час виклику.
У `kidsWithCandies(int[] candies, int extraCandies)` це параметри.
У виклику `kidsWithCandies(new int[] {2, 3, 5}, 3)` масив і число 3 — аргументи.

## 3. Чому функція бачить не всі змінні?

Локальна змінна доступна лише у своїй області видимості.
Інший метод не бачить локальних змінних того, хто його викликав:
потрібні дані передають через параметри або, коли це доречно, поля об'єкта.
Це зменшує випадкові залежності й дозволяє змінювати методи незалежно.

## 4. Якої довжини має бути функція?

Універсального числа рядків немає. Важливіше, щоб функція виконувала одну
зрозумілу дію і її можна було прочитати без постійних переходів.
Якщо в ній змішані читання даних, обчислення і друк або повторюються блоки,
це привід виділити окремі методи. Дуже коротка функція теж може бути незрозумілою.

## 5. Чому функція може змінити переданий масив?

Java передає аргументи за значенням. Для масиву цим значенням є посилання:
параметр отримує копію посилання на той самий об'єкт.
Тому `numbers[0] = 5` змінює спільний масив, а
`numbers = new int[3]` лише перепризначає локальний параметр.
Якщо зміни не передбачені, масив не змінюють або працюють із `clone()`.
Обидва рішення цієї практичної зберігають вхідні дані; це перевірено тестами.

## 6. Що повертати, якщо нічого не знайдено?

Це залежить від контракту. Для кількості підходить 0, для набору результатів —
порожня колекція. Для пошуку одного значення можна використати `Optional`
або `OptionalInt`; для індексу — узгоджене значення -1.
Не слід повертати 0 як «не знайдено», якщо 0 є допустимою відповіддю.
Порожній вхід і неправильний аргумент — різні ситуації.
У наших методах порожній масив дає відповідно 0 та порожній список.
