# Практична 4: Git — віддалені репозиторії

`fetch` отримує віддалені коміти, не змінюючи робочі файли; `pull` отримує та зливає
зміни; `push` відправляє локальні коміти. `origin` — лише звичайне ім'я remote. Tracking
branch зберігає зв'язок локальної гілки з віддаленою.

## Важливо: без нового репозиторію GitHub

PDF просить створити порожній репозиторій GitHub і редагувати його у браузері. Це суперечить
вимозі практичної 4 використати вже наявний персональний репозиторій без створення нового.
Тому сценарій демонструє всі стани на **двох локальних копіях і тимчасовому bare remote**.
Він не змінює персональний репозиторій і не потребує входу в GitHub.

Виконуйте команди з методички по черзі у двох локальних копіях і тимчасовому bare remote.
Не використовуйте для демонстрації персональний GitHub-репозиторій. Приклади станів,
які було отримано під час виконання, описані нижче та показані у скриншотах.

## Що означають кроки

1. `git remote -v` показує адреси отримання й відправлення; `git remote show origin` додає
   стан гілок і tracking-зв'язки.
2. Для реального coursework remote вже налаштований у персональному репозиторії; новий GitHub
   не створюйте. В ізольованій вправі команда `git push -u origin main` налаштовує tracking.
3. Вебкопія та локальна копія створюють різні коміти. Push від локальної копії відхиляється,
   бо вона ще не отримала віддалений коміт.
4. Після `git fetch` дві команди `git log origin/main..HEAD` і
   `git log HEAD..origin/main` показують протилежні сторони розходження. Файли при fetch
   не змінюються.
5. `git pull --no-rebase` зливає незалежні зміни; `git log --oneline --graph -5` показує
   історію перед наступним push. У сценарії для самого процесу Git задано `GIT_EDITOR=true`,
   щоб він використав стандартне повідомлення merge-коміту й не відкривав редактор `MERGE_MSG`.
6. Після отримання злитої історії вебкопія створює ще один коміт. Тільки `git fetch` оновлює
   `origin/main`, не змінюючи робочу теку.
7. `git remote rename origin github` у Git автоматично оновлює і `branch.main.remote`. Перевірте
   це через `git branch -vv` та `git config --get branch.main.remote`: у цьому випадку короткий
   `git push` продовжує працювати, а не обов'язково ламається, як обіцяє PDF.
   `upstream` — інше довільне ім'я remote.
8. `cat .git/config` показує адреси remote і налаштування tracking звичайним текстом.

Навчальні віддалені копії та всі коміти створюються окремо в тимчасовій теці під `~/dev`.
Для здачі практичної зміни надсилаються до того самого особистого GitHub-репозиторію.
