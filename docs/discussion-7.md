# Практична 7. Керування потоком виконання

## Що насправді відбувається під час `x = x + 1`?

Обчислюється права частина: читається поточне значення `x`, до нього додається 1,
а результат записується назад у `x`. Якщо було `x = 4`, стане `x = 5`.
Для `int` переповнення не породжує винятку: після `Integer.MAX_VALUE + 1`
отримуємо `Integer.MIN_VALUE`. Це не атомарна операція для спільної змінної:
у багатопотоковій програмі потрібна окрема синхронізація.

## Чим `=` відрізняється від `==`?

`=` присвоює значення, `==` порівнює. Для примітивів `==` порівнює значення,
для посилань — чи вказують вони на той самий об'єкт, а не його вміст.
Рядки за вмістом порівнюють через `equals`. У Java умова `if` має тип `boolean`:
`if (number = 3)` не скомпілюється, а `if (flag = true)` скомпілюється,
але змінить `flag`, замість перевірити його.

## Коли брати `while`, а коли `for`?

`for` зручний, коли відомий діапазон або є лічильник:
у Fizz Buzz перебираємо числа від 1 до `number`.
`while` зручний, коли повторення залежить від стану:
у Number of Steps працюємо, доки `num > 0`, а точну кількість кроків рахуємо під час роботи.
Обидва цикли можуть виражати той самий алгоритм, але форма має полегшувати читання.

## Чи можна написати будь-яку програму, маючи лише `if` і `while`?

Для вираження алгоритмів достатньо послідовності команд, розгалуження та повторення,
якщо також є операції над даними й достатня пам'ять. Тому `for`, `switch`
і рекурсію можна замінити іншими конструкціями; для рекурсії може знадобитися явний стек.
Самих двох ключових слів без обчислень, пам'яті та введення/виведення недостатньо.

## `break` посеред циклу — зручність чи поганий стиль?

`break` корисний, коли результат уже знайдено або подальша робота не потрібна:
наприклад, припинити пошук після першого збігу. Це не поганий стиль саме по собі.
Але багато виходів у вкладених циклах ускладнюють перевірку логіки.
Варто обрати просту умову, ранній вихід із методу або окремий метод,
якщо вони роблять код зрозумілішим.

## Як переконатися, що цикл колись завершиться?

Потрібно знайти величину, яка має нижню межу та зменшується на кожному кроці
(або симетрично зростає до верхньої межі). У Number of Steps невід'ємне `num`
при `num > 0` строго зменшується: непарне — після віднімання 1,
парне додатне — після ділення на 2. Тому воно досягне нуля.
У Fizz Buzz лічильник зростає до заданої межі; за умовою `number <= 10_000`,
тому переповнення лічильника немає. Тести перевіряють граничні випадки,
але самі по собі не замінюють аргумент завершення.
