# Відкрита дискусія: булева алгебра та бітові операції

## Навіщо в програмуванні окремий тип для «так» і «ні»?

`boolean` представляє логічні умови значеннями `true` або `false`. Окремий тип не дає
випадково трактувати довільне число чи текст як істину й дозволяє компілятору перевіряти
логічні вирази. У Java примітивний `boolean` має саме ці два значення.

## Як сказати `!(a && b)` людською мовою?

«Неправда, що одночасно істинні і `a`, і `b`». За законом де Моргана це те саме, що
«`a` хибне **або** `b` хибне (або обидва хибні)»: `!a || !b`.

## Чим `&&` відрізняється від `&`?

Для логічних значень `&&` виконує коротке замикання: якщо ліва частина вже `false`,
права не обчислюється. `&` обчислює обидві логічні частини. Для цілих чисел `&` — це
побітове AND, яке порівнює відповідні біти. Тому ці оператори мають різні задачі.

## Чому `x != null && x.name == "Іван"` не падає, коли `x` порожній?

`&&` працює з коротким замиканням. Якщо `x != null` дає `false`, Java не обчислює
`x.name`, тому звернення до `null` не відбувається. Для порівняння тексту в Java зазвичай
пишуть `"Іван".equals(x.name)`: `==` для об'єктів перевіряє тотожність посилань, а не
однаковість тексту.

## Як запхати 32 відповіді «так/ні» в одне число?

Використати кожен біт 32-бітного `int` як одну відповідь: `1 << i` — маска позиції `i`,
`mask |= 1 << i` вмикає відповідь «так», а `(mask & (1 << i)) != 0` перевіряє її.
У Java знаковий біт також доступний для побітових операцій, тож усі 32 позиції можна
використати, навіть коли число `int` виглядає від'ємним.

## Що швидше: `n % 2` чи `n & 1`?

Обидва вирази можуть визначити парність, але `% 2 == 0` зазвичай читається зрозуміліше.
Сучасний JIT-компілятор часто оптимізує ділення на степінь двійки, тож ручна заміна на
`& 1` не гарантує швидшого коду. Вибір оптимізації варто перевіряти вимірюванням, а не
припущенням.
