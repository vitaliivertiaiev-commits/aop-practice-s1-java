# Практична 10. Артефакти збірки

Працював з окремим Maven-проєктом `demo` у тимчасовому каталозі.
Основний `pom.xml` навчального репозиторію не змінював.

## 1. Збірка JAR

Команда `mvn package` створила `target/demo-1.0.0.jar`.
Назва складається з `artifactId` та `version` у `pom.xml`.

## 2. Вміст архіву

Через `unzip -l` переглянув файли JAR, а через `unzip -p` — маніфест.
Без `Main-Class` команда `java -jar` завершується повідомленням
`no main manifest attribute`.

## 3. Запускний маніфест

У демонстраційному проєкті налаштував `maven-jar-plugin`:

```xml
<archive>
  <manifest><mainClass>Main</mainClass></manifest>
</archive>
```

Після повторного `mvn package` у маніфесті є `Main-Class: Main`,
а `java -jar target/demo-1.0.0.jar` запускає програму.

## 4. Контрольна сума

Порівняв SHA-256 початкового JAR та його копії через `shasum -a 256`.
Суми однакові. Після дописування одного нульового байта до копії
її сума змінилася, а початковий файл залишився без змін.

## 5. Архіви релізу

Створив `release.zip` та `release.tar.gz`.
Переглянув вміст командами `unzip -l` і `tar -tzf`:
обидва архіви містять той самий JAR.

## 6. Відновлення та Git

До додавання `target/` у `.gitignore` каталог видно в `git status --short`,
після — ні. `mvn clean` видалив артефакт, а `mvn package` відновив його.
Для повторюваних архівів у demo задано сталий `project.build.outputTimestamp`.
JAR та архіви релізу до основного репозиторію не додавав.
