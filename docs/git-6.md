# Практична 6: Git — читання історії

Виконуйте команди у тому самому персональному репозиторії курсу; новий репозиторій
не створюйте. Перегляд журналу й історії файлів не змінює робочу теку. У цьому
репозиторії головний файл README називається `readme.md` (малими літерами).

У мобільному виконанні кожен незалежний блок явно обирає робочу копію через
`git -C ~/dev/aop-practice-s1-java`, оскільки поточна тека Shell може відрізнятися.
Наприклад, `git log` нижче відповідає команді
`git -C ~/dev/aop-practice-s1-java log` у цій робочій копії.
[Скриншоти, фактичні скорочення виводу та результат публікації тега](evidence-6.md#git).

## 1. Порівняйте варіанти журналу

```bash
git --no-pager log
git --no-pager log --oneline -5
git --no-pager log --oneline --graph --decorate -20
```

`--graph` малює лінії гілок, `--decorate` підписує гілки й теги.

## 2. Звужуйте журнал різними фільтрами

```bash
git --no-pager log -5 --stat
git --no-pager log --author="ім'я автора з журналу" --oneline
git --no-pager log --since="2 weeks ago" --oneline
git --no-pager log --oneline -- readme.md
```

Фільтри відповідають на питання про розмір змін, автора, час і історію одного файла.

## 3. Покажіть коміт за хешем і відносним ім'ям

```bash
git --no-pager log --oneline -5
git --no-pager show HEAD~2
```

Порівняйте `HEAD~2` із третім комітом згори в журналі: це має бути той самий коміт.
За бажанням візьміть його повний хеш і виконайте `git --no-pager show <хеш>`.

## 4. Знайдіть автора рядка

```bash
git blame readme.md | head -20
```

Візьміть хеш одного з показаних рядків і підставте замість `<хеш>`:

```bash
git --no-pager show <хеш>
```

`blame` показує коміт для кожного рядка; `show` розгортає цей коміт і його зміни.

## 5. Знайдіть появу або зникнення тексту

```bash
git --no-pager log -S "Практична 6" --oneline -- readme.md
```

`-S` знаходить коміти, в яких змінилася кількість входжень заданого тексту.

## 6. Створіть тег-закладку

Спершу переконайтеся, що такого тегу ще немає:

```bash
git tag -l
```

Якщо `v1.0.0` відсутній, створіть тег і перевірте, на який коміт він указує:

```bash
git tag v1.0.0
git tag -l
git --no-pager show v1.0.0
git --no-pager log --oneline --decorate -3
```

Якщо тег уже існує, не перезаписуйте його: виберіть унікальну назву. Щоб опублікувати
новий тег у тому самому remote, виконайте `git push origin v1.0.0`.

## 7. Задайте власний формат журналу

```bash
git --no-pager log --format='%h | %ad | %an | %s' --date=short -10
git --no-pager log --format='%C(yellow)%h%C(reset) %s %C(dim)(%ar)%C(reset)' -10
```

`%h` — короткий хеш, `%ad` — дата, `%an` — автор, `%s` — тема, `%ar` — відносний час.

## 8. Подивіться на історію згори

```bash
git --no-pager shortlog -sn
git --no-pager log --oneline --all --graph -30
```

`shortlog -sn` групує кількість комітів за авторами; `--all` показує коміти всіх гілок.
