# Практична 9. DevOps: від коду до програми

Вправи виконуються в окремому навчальному каталозі.

## 1. Компіляція та запуск

`javac Main.java` створює `Main.class`. Команда `java Main` запускає клас,
а не файл із розширенням. Програма друкує привітання.

## 2. Помилки компіляції та виконання

У `Broken.java` пропущено крапку з комою: `javac` завершується з помилкою,
а `Broken.class` не створюється.
`Boom.java` компілюється, але звернення до індексу 10 масиву довжини 3
спричиняє `ArrayIndexOutOfBoundsException` під час запуску.
Копія цього коду в `Other.java` не компілюється через невідповідність
імені файла публічному класу `Boom`. Для кожного випадку перевіряється exit code.

## 3. Classpath

```bash
mkdir -p src out
mv Main.java src/
rm Main.class
javac -d out src/Main.java
ls out
java Main
java -cp out Main
```

Старий `Main.class` прибрано з кореня: інакше запуск без `-cp` знайшов би
цю копію, і помилка не відтворилася б. Байткод тепер лежить в `out`,
тому перший запуск не знаходить клас, а другий працює.

## 4. Версії

`java -version` показує JVM, `javac -version` — компілятор.
Для вправ використовується JDK 25.0.2. Байткод новішої версії може
не запускатися на старішій JVM.

## 5. Maven

Окремий мінімальний проєкт `demo` містить `src/main/java/Main.java`
та `pom.xml`. Як у завданні, для цього demo вказано source/target 17.
Основний навчальний репозиторій залишається з release 25.

```bash
mvn compile
ls target/classes
java -cp target/classes Main
```

Maven сам знаходить вихідні файли за структурою проєкту.

## 6. Життєвий цикл

```bash
mvn test
mvn clean
ls
mvn compile
ls target
```

У мінімальному demo власних тестів немає: `mvn test` проходить етапи
компіляції й пошуку тестів, але не підтверджує перевірку алгоритмів.
`clean` видаляє `target`, повторна компіляція відновлює його.
Тести Java-завдань запускаються окремо в основному Maven-проєкті.
