# Git: навіщо потрібен контроль версій

Git зберігає історію змін у проєкті. Він допомагає:

- бачити, що і коли змінилося;
- порівнювати версії файлів і знаходити причину помилки;
- повернутися до попереднього стану;
- працювати над різними змінами у гілках;
- об'єднувати роботу кількох людей і розв'язувати конфлікти.

Git — розподілена система: повна копія історії може зберігатися на комп'ютері кожного
учасника. GitHub — окремий сервіс для зберігання та спільного перегляду віддалених репозиторіїв.

## Основні поняття

- **Робоча директорія** — файли, які зараз редагуються.
- **Індекс (staging area)** — зміни, підготовлені до наступного збереження.
- **Коміт** — зафіксований набір змін з описом і посиланням на попередню історію.
- **Віддалений репозиторій** — копія на GitHub чи іншому сервері.

## Типовий цикл

```bash
git status
git add src docs readme.md
git status
git commit -m "Complete practice 1"
git push
```

`git add` готує вибрані зміни, `git commit` записує їх до локальної історії, а `git push`
передає коміти до віддаленого репозиторію. Після push варто відкрити GitHub і перевірити,
що потрібні файли та останній коміт з'явилися онлайн.
