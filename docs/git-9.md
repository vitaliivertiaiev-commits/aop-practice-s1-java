# Практична 9. Git: гілки

Вправи виконуються в тимчасовому локальному репозиторії.
Основна гілка репозиторію курсу не перемикається і не видаляється.

## 1. Гілка та HEAD

`cat .git/refs/heads/main` показує хеш початкового коміту.
У `.git/HEAD` записано `ref: refs/heads/main`: HEAD посилається на гілку.

## 2. Нова гілка

`git switch -c feature/notes` створює гілку на тому самому коміті.
Хеші `main` і `feature/notes` спочатку однакові: копія проєкту не створюється.

## 3. Коміт зсуває лише поточну гілку

Після додавання рядка `нотатка` і коміту в `feature/notes`
її хеш змінюється, а `main` залишається на базовому коміті.
`git log --oneline --all --graph` показує обидві гілки.

## 4. Перемикання змінює робочі файли

У `feature/notes` файл має два рядки. Після `git switch main`
залишається лише `база`. Повернення у `feature/notes` повертає нотатку.

## 5. Detached HEAD

Після `git switch --detach HEAD~1` HEAD вказує безпосередньо на коміт.
У `.git/HEAD` тепер хеш, а не `ref:`. `git status` описує detached HEAD,
а `git switch -` повертає на попередню гілку.

## 6. Видалення невлитої гілки

З гілки `main` команда `git branch -d feature/notes` відмовляє:
нотатка ще не включена в main. `git branch -D feature/notes` видаляє ім'я.
Сам коміт знайдено в `git reflog --all`, його тип і вміст перевірено
через `git cat-file -t` та `git show`. Видалення гілки не стирає об'єкт коміту.

## 7. Перейменування

```bash
git switch -c experiment
git branch -m experiment/bitwise
git branch -a
```

Поточна гілка отримує нове ім'я. У тимчасовому репозиторії віддаленого
немає, тому список містить лише локальні гілки.
