# Практична 5: DevOps — змінні та перший Bash-скрипт

Запускати вправи потрібно через згрупований сценарій:

```bash
bash scripts/practice-5.sh devops
```

Щоб виконати DevOps, а потім Git одним запуском і не вводити команду вдруге:

```bash
bash scripts/practice-5.sh all
```

Він виконує команди у новій теці `~/dev/devops5.*`; файли проєкту не змінюються.
У режимі `all` Git починається після завершення DevOps. Після кожного блока сценарій
зупиняється для скриншота й чекає Enter.

## 1. Змінні та лапки

```bash
NAME=world
echo "hello $NAME"
bash -c 'NAME = world'
FILE="мій файл.txt"
echo "$FILE"
echo '$FILE'
touch $FILE
touch "$FILE"
```

У присвоєнні не можна ставити пробіли біля `=`. Подвійні лапки підставляють змінну,
одинарні показують буквальний текст. Без лапок значення з пробілом розбивається на
окремі аргументи. Сценарій створює ці навчальні файли лише у своїй тимчасовій теці
та одразу видаляє їх.

## 2. Shebang і права на виконання

Файл `greet.sh` починається з `#!/bin/bash`, використовує `set -euo pipefail`,
аргумент `$1` і лічильник аргументів `$#`. Спочатку прямий запуск `./greet.sh`
без `chmod +x` очікувано завершується помилкою. Після `chmod +x greet.sh` файл
запускається як програма.

## 3. Прямий запуск і запуск через Bash

`./greet.sh` потребує права на виконання та використовує shebang. `bash greet.sh`
явно запускає інтерпретатор, тому самому файлу право на виконання не потрібне.

## 4. `set -euo pipefail`

Сценарій порівнює `unsafe.sh`, який продовжує роботу після невдалого `cd`, із
`safe.sh`, який зупиняється через `set -euo pipefail`. Окремий `strict.sh`
показує, як `set -u` зупиняє виконання через невизначену змінну. Очікувані помилки
вправ безпечно обробляються навчальним сценарієм.

## 5. Скрипт із аргументами та підстановкою команд

`count.sh` приймає каталог і розширення, зберігає результат `find ... | wc -l`
у змінну через `$(...)` та друкує кількість файлів. Сценарій перевіряє каталог
із пробілом у назві й розширеннями `txt` та `md`.

## Важливо

У робочих сценаріях беріть змінні у подвійні лапки й використовуйте
`set -euo pipefail`, щоб уникати поділу шляхів, тихого продовження після помилок
та непомічених помилок у конвеєрі.
