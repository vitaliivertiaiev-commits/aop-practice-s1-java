# Практична 10. Рекурсія

## 1. Що таке рекурсія?

Це виклик функцією самої себе для меншої частини задачі.
Наприклад, сума чисел від 1 до `n` — це `n` плюс сума від 1 до `n - 1`.

## 2. Навіщо потрібен базовий випадок?

Це умова, за якої відповідь уже відома й наступний виклик не потрібен.
Для суми можна зупинитися на `n == 0` і повернути 0.
Кожен наступний виклик має наближати до цієї умови.

## 3. Де рекурсія трапляється поза програмуванням?

У вкладених папках, матрьошках, родоводі та розгалуженні дерев.
Частина має схожу будову на ціле, тому її можна розглядати тим самим способом.

## 4. Що буде без зупинки?

У Java кожен виклик займає місце у стеку. Якщо виклики не припиняються,
пам'ять стека закінчиться і виникне `StackOverflowError`.
Потрібні базовий випадок і зміна аргументів у його напрямку.

## 5. Чому Фібоначчі прискорюється після маленької правки?

Наївна рекурсія багато разів обчислює ті самі значення:
`fib(n - 1)` і `fib(n - 2)` мають спільні підзадачі.
Її час експоненційний, тому `fib(50)` потребує дуже багато викликів.
Мемоізація зберігає готові відповіді: кожне число обчислюється один раз,
час стає `O(n)`, а пам'ять — `O(n)`.
Також потрібен `long`: значення `fib(50)` дорівнює `12586269025`
і не вміщується в Java `int`.

## 6. Рекурсія чи цикл?

Для простого проходу масивом зазвичай обираю цикл: він не збільшує стек.
Для дерев, вкладених структур і поділу задачі рекурсія часто зрозуміліша.
Враховую обмеження даних: Java не гарантує оптимізацію хвостових викликів,
тому дуже глибоку рекурсію краще замінити циклом або обмежити її глибину.
