# Практична 11. Конфлікти злиття

Вправи виконав в окремому тимчасовому Git-репозиторії з гілкою `main`.
Історію основного навчального репозиторію не змінював.

## 1. Конфлікт однакових рядків

У гілках `main` і `dev` змінив один рядок `config.txt` по-різному.
Під час `git merge dev` Git зупинив злиття та вставив маркери конфлікту.
`git status` показав файл як нерозв'язаний.

## 2. Зміни в різних файлах

Після `git merge --abort` додав окрему зміну в `notes.txt` у `dev`.
Наступне злиття виконалося без конфлікту для цього файла; зміна потрапила в `main`.

## 3. Ручне розв'язання

Виправив `config.txt`, прибрав усі маркери, додав файл через `git add`
та завершив злиття командою `git merge --continue`.

## 4. Варіанти `ours` і `theirs`

Повторно створив конфлікт і переглянув обидві версії через
`git checkout --ours config.txt` та `git checkout --theirs config.txt`.
Після вибору однієї версії додав файл до індексу й завершив злиття.

## 5. Скасування злиття

Окремо виконав `git merge --abort` під час конфлікту.
Робоча тека повернулася до стану до злиття.

Конфлікт означає, що Git не може сам вибрати правильну версію однакових рядків.
Потрібно відредагувати файл, позначити розв'язання через `git add`
і завершити злиття або скасувати його через `git merge --abort`.
