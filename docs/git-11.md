# Практична 11. Конфлікти злиття

Для вправи створив тимчасовий Git-репозиторій із гілками `main` та `dev`.
Історію основного репозиторію не змінював.

У `config.txt` змінив один і той самий рядок по-різному в обох гілках.
Після `git merge dev` Git зупинив злиття; у файлі з'явилися маркери
`<<<<<<<`, `=======` та `>>>>>>>`. Перевірив конфлікт через `git status`
і `cat config.txt`.

Спочатку скасував це злиття командою `git merge --abort`. Потім у `dev`
додав рядок до `notes.txt` і знову злив гілки. `config.txt` знову конфліктував,
але зміну в `notes.txt` Git підготував до злиття автоматично.

Прибрав маркери з `config.txt`, залишив потрібне значення, виконав `git add`
і завершив злиття командою `git merge --continue`.

Ще двічі створив конфлікт і перевірив `git checkout --ours config.txt`
та `git checkout --theirs config.txt`: перша команда залишила версію `main`,
друга — версію `dev`. Після кожного вибору виконав `git add config.txt`
і `git merge --continue`. Наприкінці знову виконав `git merge --abort`
і перевірив, що робоча тека чиста.
