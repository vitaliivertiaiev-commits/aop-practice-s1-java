# Відкрита дискусія: масиви

## Навіщо масив, якщо можна завести сто окремих змінних?

Масив зберігає багато значень одного типу під одним іменем. До елементів можна
звертатися за індексом, а обробку повторювати циклом. Зі ста окремими змінними
такий код був би важким для читання, обробки й розширення.

## Що таке індекс і чому програма падає з «index out of bounds»?

Індекс — це позиція елемента в масиві. У Java індекси починаються з `0`, тому для
масиву довжини `n` дозволені індекси від `0` до `n - 1`. Звернення поза цими межами
спричиняє `ArrayIndexOutOfBoundsException`.

## Чому розмір звичайного масиву не можна змінити після створення?

Під час створення масиву Java виділяє пам'ять для фіксованої кількості елементів,
а поле `length` не змінюється. Щоб отримати інший розмір, створюють новий масив і
за потреби копіюють елементи. Для змінної кількості значень можна використати
`ArrayList`.

## Чому прохід по рядку 2D-масиву швидший за прохід по колонці?

Масив масивів у Java зберігає кожен рядок окремим масивом. Елементи одного рядка
лежать послідовно в пам'яті, тож процесор може ефективно завантажувати сусідні
значення в кеш. Прохід по колонці переходить між різними рядками й частіше
промахується повз кеш.

## Чому масиви нумеруються з нуля, а не з одиниці?

Адреса елемента обчислюється від початку масиву: базова адреса плюс індекс,
помножений на розмір елемента. Для першого елемента зміщення дорівнює нулю,
тому індексація з нуля природно відповідає цьому розрахунку.

## Чому додати елемент у кінець масиву дешево, а на початок — дорого?

У звичайного масиву розмір фіксований, тож додати елемент без нового масиву
неможливо. Якщо є вільна місткість у масиві-обгортці на кшталт `ArrayList`,
додавання в кінець зазвичай дешеве; іноді потрібне збільшення масиву з копіюванням.
Додавання на початок вимагає зсунути решту елементів, тобто виконує `O(n)` роботи.
