# Практична 3: DevOps — будова команд і діагностика

Команда зазвичай має вигляд `програма параметри шлях`: у `ls -la ~/dev` програма — `ls`,
прапорці — `-l` та `-a`, шлях — `~/dev`. Короткі прапорці можна об'єднати, довгі пишуться
з двома рисками.

## 1. Порівняйте форми запису `ls`

```bash
ls -l -a ~/dev
ls -la ~/dev
ls -l --all ~/dev
```

У PDF третій рядок подано як `ls --all ~/dev`, але він не еквівалентний двом першим:
`--all` вмикає показ прихованих файлів, але не довгий формат. `-l --all` зберігає обидві
дії та є правильною довгою формою для `-la`.

## 2. Знайдіть параметр у вбудованій довідці та посібнику

```bash
ls --help | head -30
man ls
```

У `man ls` введіть `/human` і Enter, щоб знайти згадку про зрозуміле людині подання розміру.
Натисніть `q`, щоб закрити посібник. Перевірте результат:

```bash
ls -lh ~/dev
```

`-h` показує розмір у зручних одиницях, наприклад K або M.

У середовищі Replit програма `man` може бути встановлена без сторінки `ls`.
Мобільний сценарій у такому випадку завантажує справжню сторінку GNU coreutils із
Debian manpages і відкриває її через `man -l`; він не підміняє посібник вигаданим текстом.

## 3. Прочитайте повідомлення про три помилки

Виконуйте команди окремо й дочитуйте повідомлення до кінця:

```bash
cat no-such-file.txt
cd /no/such/dir
ls --definitely-unknown-option
```

Команда `cd` — вбудована команда shell, тому її повідомлення про помилку може мати інший
вигляд, ніж повідомлення `cat` чи `ls`. У вправі з PDF наведено `ls -Z` як невідомий
прапорець, але у GNU `ls` цей прапорець відомий і пов'язаний із SELinux. Тому для надійної
перевірки невідомого параметра використовуйте довгий вигаданий прапорець вище.

## 4. Перевірте код завершення

```bash
ls ~
echo $?
ls /no/such/dir
echo $?
true; echo $?
false; echo $?
```

`$?` містить код завершення **останньої** команди: `0` означає успіх, ненульове значення —
помилку. Тому `echo $?` треба запускати відразу після команди, результат якої перевіряєте.

## 5. Перевірте зв'язування через `&&`

```bash
mkdir -p ~/dev/ok-dir && cd ~/dev/ok-dir && echo "успіх"
cd /no/such/dir && echo "цього не буде надруковано"
```

Наступна частина ланцюжка `&&` запускається лише після успішного завершення попередньої.
Друга команда `echo` не запуститься, бо перейти в неіснуючу теку не вдалося.

## 6. З'ясуйте, що запускає shell

```bash
type ls
type cd
command -v java
which git
```

`type` може показати звичайну програму, alias або вбудовану команду. Наприклад, `cd` має
бути вбудованою командою, оскільки окремий процес не міг би змінити теку батьківського
shell.
