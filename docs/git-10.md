# Практична 10. Злиття гілок

Вправи виконав в окремому тимчасовому репозиторії з гілкою `main`.
Історію основного навчального репозиторію не змінював.

## 1. Fast-forward

Створив `feature`, додав рядок і зробив коміт.
`git merge feature` пересунув `main` уперед без нового коміту.
У журналі видно одну лінію.

## 2. Merge commit

Після навчального `reset --hard HEAD~1` створив `feature2`.
Першу фічу зберіг у ній через `git merge --ff-only feature`.
Окремо додав зміни у `feature2` та `main`, потім виконав
`git merge feature2 --no-edit`. З'явився коміт злиття.

## 3. Два батьки

Переглянув об'єкт через `git cat-file -p HEAD`.
Два рядки `parent` відповідають вершинам `main` та `feature2`
безпосередньо перед злиттям.

## 4. Примусове злиття

Створив `feature3`, зробив коміт і виконав
`git merge --no-ff feature3 --no-edit`.
Хоча fast-forward був можливий, Git створив коміт з двома батьками.

## 5. Тільки fast-forward

Змінив і `feature4`, і `main`. Команда `git merge --ff-only feature4`
відмовилася від злиття: гілки розійшлися.
Після відмови стан `main` не змінився.

## 6. Очищення

Через `git branch --merged` перевірив злиті гілки.
`git branch -d feature feature2 feature3` видалив їх без примусу.
Незлиту `feature4` залишив.
